# Development Journal

This project keeps a lightweight **development journal** in `docs/journal/` to record completed tasks, notable changes, and decisions.

## When to write an entry

Write a journal entry when you **complete a task** (especially if it changes behavior, config, data model, pipeline flow, or UX).

Good candidates:
- Completed roadmap deliverables or a meaningful chunk of work
- Bug fixes with non-obvious root causes
- Refactors that change architecture or patterns
- Trade-offs/decisions you’ll want to remember later

## File naming

Use one file per entry:

`YYYY-MM-DD-short-slug.md`

Examples:
- `2026-02-07-add-development-journal.md`
- `2026-02-10-fix-stash-graphql-timeout.md`

## Entry template (recommended)

```md
# <Title> - <Month Day, Year>

## Overview

## Implementation Approach

## Changes Made

### Files Created

### Files Modified

### Files Deleted

## Challenges Encountered

## Observations

## Trade-offs

## Next Steps (Future Considerations)

## Testing Notes
```

Keep entries factual and skimmable: what changed, why, key files touched, and anything surprising.
